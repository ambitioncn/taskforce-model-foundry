# v0.3.0 — durable workers and domain-neutral quality gates

This release makes long local training and evaluation jobs easier to supervise
without coupling Foundry to any one task domain.

- `tmf train/evaluate --background` return durable request IDs; status,
  cancellation and explicit retry operations expose the worker lifecycle.
  Linux systemd user units isolate workers from the calling CLI/Gateway process
  where available. Direct-detached fallback reports its weaker durability.
- HF/PEFT evaluation now computes holdout loss, greedy predictions and
  validation loss in one model load per side. Training token usage and
  evaluation resource/device reporting now reflect work actually performed.
- Projects can freeze an external-quality contract before training and bind a
  project-owned scorer report to the job, technical evaluation and checkpoint.
  Failed or missing external gates block export. Domain suites, rubrics,
  judges and thresholds are deliberately **not** included in Foundry.
- Model cards no longer imply that all non-synthetic project data is synthetic.

Verification: 244 Node tests passed with 0 failures/skips before release prep;
the same 31B smoke adapter's loss values and 40/40 prediction digests matched
the previous evaluation while wall time fell from 3487.742s to 1451.132s.
That smoke candidate still failed one of two predeclared technical gates and
was **not** exported or accepted as a quality improvement.

Limits: no physical power-loss or disk-exhaustion proof, no full business
benchmark result, and no domain-specific quality acceptance is claimed by
this release. A project-owned scorer must supply and substantiate its own
external evidence.
